# Entity Server 소개 · 장점 · 도입 포인트

## 한 줄 소개

Entity Server는 **엔티티 JSON 정의만으로 DB 스키마, CRUD API, 권한/보안, 운영 도구를 빠르게 구성**할 수 있는 백엔드 서버입니다.

## 어떤 문제를 해결하나

- 반복적인 CRUD 백엔드 개발 비용을 줄이고 싶을 때
- 서비스별로 인증/권한/감사로그/이력 관리를 매번 새로 구현하기 어려울 때
- 빠른 MVP 출시 후 점진적으로 운영 안정성을 높이고 싶을 때

## 핵심 장점

- **빠른 개발 속도**: 엔티티 정의 중심으로 API와 스키마를 함께 관리
- **운영 기능 내장**: 히스토리/리비전, 롤백, 스크립트 기반 운영 작업 지원
- **보안 기본기**: JWT, API Key/HMAC, RBAC, OAuth 2.0(Google/GitHub/Naver/Kakao/커스텀) 지원
- **암호화 강점**: XChaCha20-Poly1305 기반 데이터/패킷 암호화 옵션 제공
- **데이터 유연성**: 다중 RDB(MySQL/MariaDB/TiDB/PostgreSQL/SQLite/MSSQL) + 선택형 DataStore 지원
- **배포 단순성**: Go 단일 바이너리 중심으로 배포/업데이트 표준화
- **확장성**: 파일 스토리지, SMTP, Push, 백업 등 기능을 설정으로 확장
- **일관성**: 프로젝트 간 규칙과 데이터 접근 패턴을 표준화

## 왜 써야 하나

- 백엔드를 처음부터 직접 구축하면, 비즈니스 로직보다 인프라성 코드에 시간이 많이 소모됩니다.
- Entity Server는 이 공통 영역을 표준화해 **팀이 도메인 로직에 집중**하게 도와줍니다.
- 특히 작은 팀/짧은 일정에서 **초기 출시 속도와 운영 안정성의 균형**을 맞추기 좋습니다.

## 이런 팀/서비스에 특히 적합

- 사내 관리 시스템, B2B 운영도구, 데이터 중심 서비스
- CRUD 비중이 높고 권한 제어가 중요한 백엔드
- 빠르게 프로덕션에 올리고 운영 자동화를 붙여야 하는 팀

## 도입 전 체크포인트

- 엔티티 중심 모델링 방식에 팀이 동의하는가
- 고유한 복잡 트랜잭션/초고성능 실시간 처리 요구가 핵심인지
- 인증/권한/감사 정책을 기본 제공 방식에 맞출 수 있는지

## 이런 경우는 신중히 검토

- 도메인 로직보다 커스텀 쿼리 엔진/이벤트 처리 인프라가 핵심인 경우
- 프레임워크 내부를 깊게 커스터마이징해야 하는 경우
